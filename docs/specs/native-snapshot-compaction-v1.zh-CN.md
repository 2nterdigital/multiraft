# 原生持久快照压缩 v1（待验证实现）

本契约仍等待精确源码的 G1/G2 验证。唯一提案与任务清单位于 ech0 的
`establish-durable-raft-log-compaction`，这里不建立第二份实施计划。

复用锁定 OpenRaft 的 builder、install、启动恢复和原生 RPC。普通构建可因
资源或字节上限返回延期；强制构建必须返回 builder，能覆盖当前切点的已有
持久快照可以复用，否则安全失败，不伪造空快照。旧 FSM 的有界捕获默认拒绝，
既有非持久模式保持原接口；应用自己的更小上限继续有效。

NativeDurable 要求 Data 或更强的文件日志，采用手动策略。Data/All 等级在
保存 committed 时同步已有字段，并按日志 IO 顺序落盘，避免依赖下一次写入或
在线 peer 才能找回最后的已提交后缀。保留日志数为
0–65536，默认 1024；应用快照字节数为 1–67108864，默认上限 64 MiB。
Disabled 不再继承旧的 5000 条日志自动快照策略。Standby HTTP/catalog/daisy
恢复仍被隔离。原生传输的元数据与封装预算至多 1 MiB，快照发送和接收有明确
并发界限；超限字节在不必要的复制与安装之前拒绝。

每个 Group 使用已有 catalog 的不可变代文件，保存 Group 身份、完整
SnapshotMeta、应用字节、长度和校验和。文件与目录同步后才能原子切换 active
清单。损坏 active 不会静默回退到旧代；旧切点的晚到构建不能覆盖较新的安装。
相同切点的等价业务编码不被强制规范化。启动由 OpenRaft 安装已验证的持久
快照并重放后缀；bridge 检查原生 apply 序列的连续性，不另建重放流程。

维护入口仅作用于本节点的一个 Group。Preparing、Submitted、观测完成和
Unconfirmed 分开：捕获准备不是提交，trigger 返回不是完成。完成还需要
实际构建结束、持久 provider 和原生 snapshot/purge 事实，保留策略无需删除
前缀时单独说明。状态是本地采样，不承诺健康、可写、净磁盘节省或请求独占因果。
每 Group 至多一个显式操作，每节点至多一个快照构建；等待者断开不会取消已持有
资源的工作。簿记有界、可丢弃，重启不重放 HTTP 意图。

关闭先拒绝新维护入口，再在统一截止时间内等待已有原生工作；无法静止时返回
现有失败路径。G1 必须在指定实验室验证精确后端提交、依赖锁、崩溃切点和每种
正向恢复形态的五次运行。后端 dev 发布需要单独授权；G2 对齐精确消费者源码后
验证真实 Meta/Message。进程崩溃结果不构成主机断电或容量/SLO 认证。
